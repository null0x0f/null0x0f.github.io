# 重要功能实现逻辑

## 读取设备的电压等参数（异步处理）

### 五个参数数组，从 PLC 获取 Modbus 地址读入

不管是读取还是写入，都避免连续请求。

在收到上一个请求的回复后，再发送下一个请求，在读写过程中都使用异步处理。

```cpp
QModbusDataUnit unit = readRequestQueue.dequeue();

if (auto *reply = modbusDevice->sendReadRequest(unit, 1)) {

    // 异步处理
    // 在绝大多数情况下，Modbus 请求是异步的，
    // 也就是说你发出请求后，设备还没来得及返回数据，
    // 这时 isFinished() 返回 false。
    if (!reply->isFinished()) {

        // 没完成这个请求，插入队列
        readReplyToAddress.insert(reply, unit.startAddress());

        /*
         * 请求还在进行中，连接信号与槽，
         * 提前告诉 Qt：
         * “等数据回来了，自动通知我”
         *
         * finished 的判断和触发，
         * 全部由 Qt 框架自动完成。
         *
         * 你只需要专注于：
         * “收到信号后怎么处理数据”
         */
        connect(
            reply,
            &QModbusReply::finished,
            this,
            &ModbusWorker::readReady
        );

    } else {
        delete reply;
        processNextRequest();
    }
}
```

`readReady()` 函数负责处理返回的数据。

### 异步处理机制类比

假设你是老师，要批改 7 份作业，每份作业就是一个读取请求：

1. 你（老师）把第一份作业交给学生（设备）批改，对应 `processNextRequest()`。
2. 学生批改完后，敲门告诉你“批改好了”，对应设备返回数据，Qt 自动调用 `readReady()`。
3. 你拿到作业，登记成绩，对应 `readReady()` 解析数据。
4. 你看还剩几份没批改，如果还有，就再交下一份给学生，对应在 `readReady()` 中再次调用 `processNextRequest()`。
5. 全部批改完后，你通知班主任“成绩都出来了”，对应 `emit dataUpdated`。

这种方式可以避免一次发送大量 Modbus 请求造成通信阻塞。

## 数据更新关键代码

每次 `timeout`，都会自动调用 `connect` 的 lambda 函数，进而调用 `updateBarSeries()`，刷新柱状图的数据，并更新 UI 上的标签。

```cpp
connect(
    &timer,
    &QTimer::timeout,
    this,
    [this]() {

        // 每次 timeout，都会自动调用这个 lambda 函数
        updateBarSeries();

        // UI 更新
        ui->reportLabel_1->setText(
            QString::number(reportDatas[1], 'f', 3)
        );

        ui->reportLabel_5->setText(
            QString::number(reportDatas[5], 'f', 3)
        );

        ui->reportLabel_6->setText(
            QString::number(reportDatas[6], 'f', 3)
        );
    }
);
```

当窗口显示时启动定时器，窗口隐藏时停止定时器。

这样可以保证只有在窗口可见时才定时刷新数据，节省资源。

```cpp
void CellVoltageViewDialog::showEvent(QShowEvent *event)
{
    timer.start(
        int(ui->timeStepSpinBox->value() * 1000)
    );

    QDialog::showEvent(event);
}

void CellVoltageViewDialog::hideEvent(QHideEvent *event)
{
    timer.stop();

    QDialog::hideEvent(event);
}
```

### 整体实现逻辑

1. 窗口显示时，`showEvent()` 被触发，定时器 `timer` 启动。
2. 定时器每隔一段时间（由 `timeStepSpinBox` 控件决定）发出 `timeout` 信号。
3. 每次 `timeout`，自动调用 `connect` 中的 lambda。
4. lambda 调用 `updateBarSeries()`，刷新柱状图数据。
5. 同时更新 UI 上的相关标签。
6. 窗口隐藏时，`hideEvent()` 被触发，定时器停止。
7. 窗口隐藏后不再刷新数据。

# AutoCurrentWriter 模块

## 文件信息

* 文件名：`autocurrentwriter.cpp`
* 功能：自动电流写入控制器，实现从 Excel 加载写入计划并定时执行

## 功能流程

```text
用户选择 Excel 文件
        ↓

        ↓
targetDateTimes / currentValues
        ↓
fileWatcher 开始监控文件
        ↓
用户点击“开始自动写入”
        ↓

        ↓
timerAutoCurrentWrite 每秒触发 handNextCurrentWtite()
        ↓
检查是否到达目标时间
        ↓
到达目标时间 → 执行写入
        ↓
┌──────────────────────────────────────────────┐
│ Excel 文件被修改                             │
│       ↓                                      │
│ onExcelFileChanged() 被触发                  │
│       ↓                                      │
│ 延迟 1 秒 → loadExcelData(path)              │
│       ↓                                      │
│ 如果正在写入 → recalculateWriteIndex()      │

```

# 多线程迁移

## 1. 线程创建

```cpp
modbusThread = new QThread(this);

modbusWorker = new ModbusWorker;

modbusWorker->moveToThread(modbusThread);
```

其中：

* `modbusThread` 是一个 `QThread`，代表一个独立线程
* `modbusWorker` 是自定义的通信处理对象，继承自 `QObject`
* `moveToThread()` 把 `modbusWorker` 的线程归属切换到 `modbusThread`

也就是说：

> `modbusWorker` 的事件循环和槽函数在 `modbusThread` 中执行。

---

## 2. 信号与槽连接

```cpp
connect(
    modbusThread,
    &QThread::started,
    modbusWorker,
    &ModbusWorker::createModbusDevice
);

// 主线程控制读取设备的连接与断开
connect(
    this,
    &MainWindow::connectDevice,
    modbusWorker,
    &ModbusWorker::connectModbusDevice
);
```

线程启动后：

```text
modbusThread 启动
        ↓
createModbusDevice()
        ↓
子线程创建通信设备
```

主线程发射：

```cpp
emit connectDevice(1);
```

然后调用子线程中的：

```cpp
connectModbusDevice()
```

---

# 3. 子线程与主线程的交互

子线程向主线程反馈数据状态：

```cpp
connect(
    modbusWorker,
    &ModbusWorker::deviceState,
    this,
    [this](int state) {
        // 获取设备状态
    }
);

connect(
    modbusWorker,
    &ModbusWorker::deviceStateResponse,
    this,
    ...

```

整体关系：

```text
                主线程
                  │
                  │ 发起请求
                  ↓
           ModbusWorker
                  │
                  │ 子线程执行
                  ↓
             Modbus通信
                  │
                  │ 数据返回
                  ↓
           ModbusWorker
                  │
                  │ signal
                  ↓
                主线程
                  │
                  ↓

```

`modbusWorker` 在子线程中采集到数据后，通过信号把数据传递给主线程。

主线程的槽函数，例如：

```cpp
updateDataAndUI()
```

在 UI 线程中执行，负责更新界面。

# Debug Point

## inline

在 `reportviewdialog.h` 文件中定义：

```cpp
inline int indexof(
    float value,
    const std::array<float, 125>& arr,
    float epsilon = 1e-4
)
{
    for (size_t i = 0; i < arr.size(); ++i) {

        if (std::fabs(arr[i] - value) < epsilon)
            return static_cast<int>(i);
    }

    return -1;
}
```

### 为什么定义为 `inline`

因为多个 `.cpp` 文件包含了：

```text
reportviewdialog.h
```

如果将普通函数定义直接放在头文件中：

```cpp
int indexof(...)
{
    ...
}
```

然后多个 `.cpp` 都包含这个头文件，就可能产生链接阶段的：

```text
multiple definition
```

即多重定义错误。

而将函数定义为：

```cpp
inline
```

之后，允许多个翻译单元看到相同的函数定义，链接器可以正确处理这些定义。

因此，将这种较小的函数直接定义在头文件中时，可以使用 `inline`。


写入速度很快，更适合：

* 实时数据
* 批量导出
* 高频数据记录

# 实时报表中没有进行实时更新

## 问题原因

页面数据不能实时更新。

根本原因是：

```text
m_reportData1
m_reportData2
```

只在构造函数中赋值了一次，之后没有继续更新。

每次定时器触发时，虽然会：

```text
update()
    ↓
paintEvent()
```

重新绘制页面，但是使用的仍然是旧数据。

因此页面内容不会发生变化。

---

## 根本原因

最新数据数组需要通过指针传递，才能让报表窗口访问到原始数据。

这样原始数组发生变化后，报表窗口就能获取最新数据。

这也是 C++/Qt 实时数据共享的一种常见方式。

---

# 解决方案

使用指针传递数组地址：

```cpp
void ReportViewDialog::setExternalDataSource(
    const std::array<float, 125>* pData1,
    const std::array<float, 44>* pData2
)
{
    m_externalData1 = pData1;
    m_externalData2 = pData2;
}
```

---

## 定时器触发 updateReport

```cpp
connect(

    &ReportViewDialog::updateReport
);
```

---

```cpp
if (m_externalData1 && m_externalData2) {
```

## 数据更新逻辑

整个数据更新过程：

```text
MainWindow
    │
    │ setExternalDataSource()
    │
    ↓
传递 readDatas_1 / readDatas_2 的指针
    │
    ↓
ReportViewDialog
    │
    │ 窗口显示
    ↓
启动定时器
    │
    ↓
updateReport()
    │
    ↓
setData()
    │
    ↓
更新报表内部数据
    │
    ↓
update()
    │
    ↓
Qt 请求重绘
    │
    ↓
paintEvent()
    │
    ↓
drawReportContent()
    │
    ↓
显示最新数据
```

具体步骤：

1. `MainWindow` 调用 `setExternalDataSource()`，把最新数据的指针传递给报表窗口。
2. `ReportViewDialog` 显示窗口后启动定时器。
3. 定时器触发 `updateReport()`。
4. `updateReport()` 调用 `setData()`。
5. `setData()` 接收最新数据，并处理内容控件数据。
6. `setData()` 调用 `update()` 请求 Qt 重绘控件。
7. Qt 检测到 `update()` 后触发 `paintEvent()`。
8. `paintEvent()` 中调用 `drawReportContent()`。
9. 使用最新数据绘制报表。

# 基础数据库类（单例类）

## 单例类的设计

使用智能指针实现懒汉模式：

```cpp
std::shared_ptr<Database> Database::instance()
{
    static std::once_flag s_flag;

    std::call_once(
        s_flag,
        [&]()
        {
            data = std::shared_ptr<Database>(
                new Database("2")
            );
        }
    );

    return data;
}
```

其中：

```cpp
static std::once_flag s_flag;
```

用于保证下面的初始化只执行一次。

```cpp
std::call_once()
```

保证 lambda 表达式中的代码只执行一次。

因此：

```text
第一次调用 instance()
        ↓
创建 Database
        ↓
保存到 shared_ptr
        ↓
后续调用
        ↓
直接返回同一个对象
```

创建数据库类为单例类，使整个项目中只允许存在一个数据库对象实例，避免重复创建数据库对象。

# 智能指针不能应用的场景

## QObject 派生类

例如：

* `QWidget`
* `QTimer`
* `QDialog`
* `QObject`

Qt 本身拥有父子对象管理机制。

当 QObject 的父对象析构时，其子对象会自动被 `delete`。

例如：

```cpp
QTimer* timer = new QTimer(this);
```

这里：

```text
this
 ↓
QTimer
```

`this` 是 `QTimer` 的父对象。

当 `this` 析构时，Qt 会自动析构 `timer`。

---

## 与智能指针混用的风险

如果再使用：

```cpp
std::unique_ptr
```

或者：

```cpp
std::shared_ptr
```

管理已经拥有 Qt 父对象的 QObject，就可能出现生命周期管理冲突。

例如：

```cpp
std::shared_ptr<QTimer> timer =
    std::make_shared<QTimer>(this);
```

此时：

```text
shared_ptr
    ↓
负责 delete

Qt parent
    ↓
也负责 delete
```

可能导致重复析构。

---

## 建议

### 有父对象

例如：

```cpp
QTimer* timer = new QTimer(this);
```

这种情况下直接使用裸指针即可：

```cpp
QTimer* timer;
```

生命周期由 Qt 父子对象机制管理。

### 没有父对象

没有 Qt 父对象的普通 C++ 对象，可以考虑：

```cpp
std::unique_ptr
```

或者：

```cpp
std::shared_ptr
```

### 跨线程

如果对象需要跨线程管理，则需要根据具体生命周期和线程归属设计对象所有权。

不能简单地认为“所有对象都应该使用智能指针”。
